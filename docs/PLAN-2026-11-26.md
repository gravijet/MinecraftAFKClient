# Plan 2026-11-26: AFK-Client 3.0

Status: `todo` · `doing` · `done` (eingebaut, Tests grün) · `verified` (gegen echten Vanilla-Server bzw. live geprüft)

## Ausgangslage (gemessen am 26.11.2026 auf Xeon-1)

| Bauform | RSS | davon anonym | Threads |
|---|---|---|---|
| `ultra-afk-linux` (POV aus, Browser-Viewer an) | 106–120 MB | 103 MB | 11 |
| `premium-items-afk-linux` | 3,1–3,5 MB | 1,0 MB | 6 |

- Acht Bauformen (slim, move, items, items-web, premium, premium-items, pov, ultra) aus 13 Cargo-Features;
  der Code ist voller `#[cfg(...)]`-Weichen. Das Panel kennt seit dem Wegfall der Tarife nur noch
  Basis / Discord / POV-Freigabe und schaltet Funktionen selbst frei.
- Der Bot schwebt: Bewegung kennt keine Welt, keine Schwerkraft, keine Kollision. Läuft er über eine
  Kante, bleibt er in der Luft stehen (Kick-Gefahr „Flying is not enabled“).
- 26.3 (Protokoll 777, Release 15.09.2026) und 26.4-pre-1 (Protokoll 0x4000015D = 1073742173) fehlen.
- 26.4 ersetzt die Login-Verschlüsselung: RSA-PKCS#1 + gemeinsamer Schlüssel als IV ist durch
  X25519 + HKDF-SHA256, getrennte Schlüssel je Richtung, HMAC-Integritätsprüfung und eigene IVs ersetzt.
  Das ist der Sicherheitsfix dieser Version; er muss exakt nachgebaut werden.

## Entscheidungen (ohne Rückfrage getroffen)

| # | Entscheidung |
|---|---|
| E1 | **Zwei Bauformen**: `afk` (Standard: Chat, Befehle, Makros, Bewegung mit Physik, Anzeigetafel, Menüs, Inventar, Tastenzustand, Anti-AFK, Browser-Menü) und `afk-pov` (zusätzlich Live-Ansicht). Ein einziges Cargo-Feature `pov`. Das Panel schaltet wie bisher selbst frei. |
| E2 | Dateinamen im Release: `afk-linux`, `afk-windows.exe`, `pov-afk-linux`, `pov-afk-windows.exe`. Beide Namen gibt es heute schon; ein noch nicht aktualisiertes Panel läuft damit weiter (alte Premium-/Ultra-Dateien bleiben in seiner Ablage liegen, bis das Panel umgestellt ist). |
| E3 | Physik ist ein Nachbau von `LivingEntity.travel` / `Entity.move` / `LocalPlayer.aiStep` aus dem unverschleierten 26.x-Client: Schwerkraft 0,08, Luftwiderstand 0,98, Bodenreibung je Block, Stufenhöhe 0,6, Sprung 0,42, Sprint, Schleichen mit Kantenschutz, Wasser, Lava, Leitern, Seelensand/Honig/Schleim. Kollisionsformen je Blockzustand werden aus dem offiziellen Server-JAR erzeugt (`data/gen-physics`), nicht von Hand geschrieben. |
| E4 | Die Welt wird in beiden Bauformen gehalten, aber unterschiedlich dicht: Standard speichert je Block nur eine **Physik-Klasse** (bit-gepackt, meist 0–2 Bit), POV den Blockzustand (bit-gepackt statt 1–2 Byte je Block). |
| E5 | Mehrere MC-Accounts bleiben getrennte Prozesse (das Panel steuert jeden über seine Standardein-/ausgabe). Ziel „+0,5 MB je Account“ wird über den anonymen Speicher je Prozess erreicht; Code-Seiten der Binary teilt das Betriebssystem ohnehin zwischen allen Prozessen. |
| E6 | 26.4 wird mit Pre-Release-1-Protokoll unterstützt und im Namen `26.4` geführt. Erscheint das Release, ändert sich nur die Protokollnummer (neu ablesen mit `data/gen-protocol.py`). |
| E7 | Paket-IDs aller modernen Versionen kommen aus Mojangs eigenem Bericht (`--reports` → `packets.json`), erzeugt in `data/gen-protocol.py`; keine handgepflegten Zahlentabellen mehr. |
| E8 | Panel (afksystems.de): nur `server/binaries.js` auf zwei Bauformen umstellen, committen und pushen. Ausrollen erst nach deinem „deploy“ (wie im Panel-Plan festgelegt). |
